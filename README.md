# GZIST-Hotspot —— 校园网有线转热点工具

> 台式机走网线上校园网（一账号一设备），一键把有线网变成 WiFi 热点，给手机 / 笔记本 / 平板共享上网。
> **广州理工学院校园网实测可用**（2026-10 真机验证），其他「一账号一设备」的校园网环境同样适用。

## 为什么需要它

很多校园网是「一账号一设备」：新设备登录会把已在线的设备踢下线，两台设备就会互相踢成乒乓球。

本方案 = **只让台式机登录校园网，其他设备全部连台式机的热点**。热点客户端的流量经 Windows ICS 做 NAT 转发，从台式机的有线网出去——校园网自始至终只看到一台已认证设备，客户端隔离 / ACL 策略完全管不到热点内部（热点是两台机器之间的直连，根本不经过校园网）。

## 功能特性

- **一键开关**：双击 bat 即可，全程无需管理员权限、不弹 UAC
- **防断网设计**：自动处理 Clash TUN 冲突（TUN 与热点互斥、双向实测都会整机断网；脚本先经 mihomo 管道 API 关 TUN，成功后保持 TUN 关闭并验证直连可用）
- **失败自动回滚**：任何一步失败，自动清理半开热点状态、自动还原 TUN，保证网络始终活着
- **网卡自适应**：优先找指定 USB 网卡，找不到自动回退任意物理无线网卡，换网卡不用改配置
- **实时输出**：每一步（STEP1~STEP5）实时打印进度与结果
- **内置排障手册**：含「Wi-Fi Direct 虚拟适配器幻影化」这一疑难故障的实战修复配方

## 使用前提（开热点前必读）

能不能用起来，取决于两类条件：**网卡决定热点能不能开起来，网络环境决定连上后能不能出网**。先对照检查，再动手。

### 一、网卡条件 —— 决定热点能不能开起来

Windows 移动热点走的是 **Wi-Fi Direct（WFD）**，不是老式软AP，对无线网卡有硬性要求。

**自查命令**（10 秒出结果，下单买卡前先跑这条）：

```powershell
netsh wlan show wirelesscapabilities
```

在你的无线网卡段落里找这三行，**必须全是「支持」**：

```
Wi-Fi Direct 设备   : 支持
Wi-Fi Direct GO     : 支持
Wi-Fi Direct 客户端 : 支持
```

**实测对照**：

| 网卡 | 结果 | 说明 |
|---|---|---|
| MediaTek MT7922（Wi-Fi 6E，内置） | ✅ 完美 | 本项目主力实测卡：热点吞吐 257 Mbps+，可带 8 客户端 |
| Realtek RTL8811CU（USB，WiFi 5，绿联 CM496 等） | ❌ 不可用 | 只支持老式软AP，WFD 三项全「不支持」——**我们真实买错的卡** |
| Intel AX200 / AX210 等（Wi-Fi 6/6E，内置） | ✅ 通常支持 | 理论兼容，仍以自查命令的实际输出为准 |

**经验规律**：

- 2019 年之后的**内置**网卡（Intel AX 系列、MT7922/MT7925 等）基本都支持 WFD——**先查机器自带的网卡，大概率不用花钱买卡**
- 廉价 **USB 迷你网卡是重灾区**：很多只支持老式软AP。商家说「支持开热点」往往指软AP，与本工具无关；拿不准就收货后先跑自查命令再决定退不退
- 网卡不支持 WFD = 热点永远开不起来，而且往往是**静默失败**（脚本三重信号全 False、事件日志零记录）——这是硬件能力缺失，任何脚本都绕不过去
- 网卡支持但热点还是开不了？跳到「排障」：十有八九是「Microsoft Wi-Fi Direct Virtual Adapter」幻影化，修复配方见排障手册第 4 节

### 二、网络环境条件 —— 决定连上后能不能出网

1. **台式机必须有一段能上网的有线连接**（本项目的唯一上行）：以太网插网线且能上网。校园网环境 = 台式机先完成认证登录（可配合 [GZIST-NetKeeper](https://github.com/xiaomai1011/GZIST-NetKeeper) 自动认证 + 掉线保活，开机 20~30 秒自动完成认证）
2. **「一账号一设备」的校园网正是本项目的目标场景**：热点客户端的流量经 Windows ICS 做 NAT，从台式机的有线网统一出去——校园网自始至终只看到台式机一台已认证设备。热点本身是台式机与客户端之间的直连，不经过校园网的认证设备
3. **客户端零配置**：手机 / 平板 / 笔记本连上热点即可访问国内资源，无需装任何东西；需要国际网络时由客户端自行配置代理
4. **台式机在用 Clash 等代理软件的注意**：TUN 模式与热点**互斥**（双向实测都会整机断网）。热点期间请用「系统代理」模式——脚本会自动关闭 TUN 并在结束后保持 TUN 关闭，属正常现象
5. **不需要准备的东西**：第二台路由器 ✗、管理员权限 ✗、公网 IP ✗、额外服务器 ✗——Windows 自带的移动热点 + ICS 全部搞定
6. ⚠️ **政策提醒**：NAT 共享意味着校园网只看到一台设备，但部分学校的网络使用规定可能限制此类共享行为，请先了解并遵守学校规定，自行评估风险

## 快速开始

1. **改密码**：用记事本打开 `hotspot.ps1`，编辑开头的 `$Ssid`（热点名）和 `$Passkey`（密码，至少 8 位）两行，改成自己的（默认 `xiaomai-AP` / `wifi12345` 只是占位）
2. 确认台式机有线网能上网
3. 双击 **`开热点.bat`**，等 1~2 分钟，看到 `STEP3 result: state=On OK` 即成功
4. 手机 / 笔记本搜到热点名，连上即可上网

日常：`查状态.bat` 看状态，`关热点.bat` 关闭。若你用 Clash：**开热点期间请用「系统代理」模式，不要开 TUN**（互斥，详见 `热点-使用说明.md`）。

## 工作原理

1. 经 mihomo/Clash 的命名管道 API 关闭 TUN（避免 TUN 抢默认路由导致断网）
2. 调 Windows `NetworkOperatorTetheringManager`（WinRT）配置并启动移动热点（WFD GO）
3. Windows ICS 自动把热点客户端流量 NAT 到有线网出口
4. 三重信号交叉验证（tethering 状态 / WFD 虚拟适配器 Up / 自扫到 SSID 广播），判定真实结果
5. 失败则停止热点清理状态，并把 TUN 恢复原样

## 排障

见 **`重启后操作清单.md`**：按「快速排障 → 完整重启 → 网络重置 → 重建 WFD 虚拟适配器」顺序递进。

其中第 4 节是重点：Windows 的「Microsoft Wi-Fi Direct Virtual Adapter」设备节点可能**幻影化**（重启 / 网络重置 / DISM+SFC 都修不好），症状是热点怎么开都失败、事件日志零记录。修复配方（`pnputil` 删幻影节点 + 重初始化物理网卡）经过实战验证，照做 5 分钟可修好。

## 环境

- Windows 11（Win10 1809+ 理论可用，未测）
- PowerShell 5.1（系统自带，脚本为纯 ASCII 避免 PS 5.1 编码坑）
- 一块支持 Wi-Fi Direct 的无线网卡 + 可用的有线网络
